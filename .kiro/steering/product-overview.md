# GoBoard プロジェクト方針

## 名称

ゲームの内部名称は **GoBoard** とする。

コードおよび UI では以下の名称を使わない。

- 五目並べ
- 連珠
- Gomoku

変数名・関数名・クラス名・ファイル名・画面上の表示文字列・コメントのいずれにおいても、
ゲームそのものを指す語としては `GoBoard` を使う。

## 実装構成

実装は HTML + CSS + JavaScript を **1ファイル**で完結させる。
CSS は `<style>`、JavaScript は `<script>` としてインラインで記述し、
ファイル分割やビルド工程を挟まない。

外部ライブラリおよび CDN は使わない。
UI フレームワーク、ユーティリティライブラリ、Web フォント、アイコンセットなども対象に含める。
必要な機能はブラウザ標準の API のみで実装する。

## テスト

UI を含まないビジネスロジックについては自動テストを実装する。

| 対象 | 方針 |
|------|------|
| 盤面状態の管理、勝敗判定、手番制御などのロジック | 自動テストを書く |
| DOM 操作、描画、イベントハンドリング | 自動テストの対象外 |

この方針を満たすため、ビジネスロジックは DOM に依存しない純粋な関数・モジュールとして切り出し、
テストから参照できる形にしておく。

### テストの実行方法

外部のテストランナーは使わず、テストコードも同じ1ファイル内に記述する。
ゲーム起動時（ページ読み込み時）にテストを実行し、結果を `console.log` に出力する。

出力には各テストの成否とテスト名を含め、最後に成功数・失敗数のサマリを出す。
失敗したテストについては期待値と実際の値を出力する。

テストの失敗はゲームの動作を止めない。ログに出すだけとし、UI 側には影響させない。
