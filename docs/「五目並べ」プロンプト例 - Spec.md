# 「五目並べ」プロンプト例 - Spec

## STEP 1：Steering を Vibe で作る

Steering はプロジェクト全体に適用されるルール・方針です。
まず Vibe で会話しながら内容を決め、`.kiro/steering/product-overview.md` に記録します。

```text
このプロジェクトの方針を Steering として .kiro/steering/product-overview.md に記録してください。

内容：
- ゲームの内部名称は「GoBoard」とする
- 「五目並べ」「連珠」「Gomoku」などの名称はコード・UIに使わない
- 実装は HTML + CSS + JavaScript の1ファイルで完結させる
- 外部ライブラリ・CDN は使わない
- UIを含まないビジネスロジックについては自動テストを実装する
- テストは外部のテストランナーを使わず、テストコードも同じ1ファイル内に記述する
  - ゲーム起動時（ページ読み込み時）にテストを実行し、結果を console.log に出力する
```

## STEP 2：ゲームとして最低限の実装をする

```text
15×15の格子盤で2人が交互に石を置き、縦・横・斜めのいずれかで
同じ色の石を5つ連続で並べたら勝ちとなるボードゲームを実装したい。
先手が黒、後手が白。石を置いた場所は変更できない。
盤が埋まって勝者がいなければ引き分け。
機能名は「goboard」とする。
```

requirements.md が生成されたら、次の2点を確認してから承認します。

- 自分がやりたいことが書かれているか
- 完了の判断基準（受け入れ基準）が自分の認識と合っているか

## STEP 3：design・tasks を承認して実装する

requirements.md を承認すると design.md、次に tasks.md が生成されます。
それぞれ確認して承認すると、AI が tasks.md に沿って実装を進めます。

実装完了後、動作確認したうえでコミットします。

```text
git add index.html
git commit -m "feat: 基本ゲームの実装"
```

## STEP 4：ローカルルール追加の Spec を起動する

```text
GoBoard に次のローカルルールを追加したい。

追加するルール：
先手（黒）が石を置いたとき、その手によって「ちょうど3個の連続した並び
（両端が空いているもの）」が同時に2箇所以上できる場合は、
その手を無効とし、石を置けないようにする。

このルールのために、石が三つ並んでいる箇所をメモリに格納するようにする。
メモリの状態は石を置く度に更新。
白と黒で石が三つ並んでいる箇所があるかをログ出力（console.log）。

ルールによるチェックと無効時のメッセージ表示、ログ出力（console.log）以外は変更しない。

requirements.md には次の2点を必ず要件として含めること。
1. 修正方法：既存のゲームロジックへの影響範囲を最小にする形で追加すること
2. リグレッションテスト：既存の基本ルール（石を置く・手番交替・勝敗判定）が
   従来通り動作することを受け入れ基準として明記すること

機能名は「local-rules」とする。
```

requirements.md で、修正方法（影響範囲の最小化）とリグレッションテストの
受け入れ基準が含まれているかを確認します。

```text
（確認ポイント例：修正方法）
THEN ローカルルールの追加は既存ロジックへの影響範囲を最小にする形で実装される

（確認ポイント例：リグレッションテスト）
WHEN ローカルルールを有効にした状態で基本ルールの動作を行ったとき
THEN 既存の勝敗判定・手番交替・着手禁止はすべて従来通り動作する
```

確認できたら承認し、実装後は PR を作ってレビューを挟みます。
