# 「五目並べ」プロンプト例 - Vibe

## STEP 1：目的の共有

最初にAIへ送る「おまじない」です。
名前に頼らずルールを自分で伝える練習をするために、最初に方針をそろえます。

```text
このプロジェクトの目的は、自分で説明したルール通りのボードゲームを作ることです。
「5目並べ」「五目並べ」「連珠」「Gomoku」などの一般名称に頼らず、
これから私が説明するルールだけを正解として実装してください。
コードや画面表示では、このゲームを内部的に「GoBoard」と呼んでください。
```

## STEP 2：実装方針の作成

### 構成の相談

```text
これから2人用のボードゲームを1つ作ります。実装に入る前に方針を相談させてください。
シンプルに実装する場合、どんな構成が向いていますか。
選択肢と、それぞれの利点・欠点を教えてください。
```

### インストールなしで動かしたい場合の追加条件

```text
条件は次のとおりです。
- Webブラウザだけで動くこと
- 追加インストールなしで動かしたい
- ファイルを開くだけで遊べる形がよい
```

### 作り込み範囲の認識合わせ

```text
今回のハンズオンは短時間なので、次の要素について「今回入れる／後回しにする」を
一緒に整理してください。理由も添えてください。
- リンター・フォーマッター
- 自動テスト
- コメントの量
```

## STEP 3：ゲームとして最低限の実装をする

### 参考：最低限の完成イメージ（答え合わせ用）

参加者が自分で「最低限リスト」を作ったあと、比較・確認のために使います。

```text
次の条件を満たす対戦ゲームを作ってください。

ゲームのルール：
- 盤は 15×15 の格子。交点に石を置く
- 黒が先手、白が後手で、交互に石を置く
- すでに石がある場所には置けない
- 縦・横・斜めのいずれかで同じ色が5つ連続で並んだら、その色の勝ち
- 盤が埋まって勝者がいなければ引き分け

UI：
- 現在の手番と勝敗結果を画面に表示する
- 「最初からやり直す」ボタンを付ける

実装後、次を自分で確認して結果を報告してください。
1. 横方向に同じ色が5つ並んだら勝ちと判定されること
2. 斜め方向でも同様に判定されること
3. 石がある場所には置けないこと
```

## STEP 4：ローカルルールを足す

ローカルルールを足すときは、いきなりコードを変えさせず、
先に影響範囲を確認してから進めるのがコツです。

### 影響範囲の確認を先にさせるプロンプト

```text
今からルールを1つ追加したいです。
ただし、いきなりコードは変えないでください。

まず次の4点を整理して、私に見せてください。確認してから実装に進みます。

追加したいルール：
{ここに自分のローカルルールを言葉で書く}

出してほしい整理：
1. 修正が必要な箇所（どの関数・どの処理か）
2. この変更が影響する範囲（他のルール判定や表示に波及しないか）
3. 具体的な直し方の方針
4. 変更後に確認すべきテストケース
```

### 「三三禁止」を言葉で伝える例

「三三」という単語を使わずに、動きで説明するとこうなります。

```text
先手（黒）が石を置いたとき、その手によって「ちょうど3個の連続した並び
（両端が空いているもの）」が同時に2方向以上できる場合は、
その手を無効とし、石を置けないようにする。
```

ただし、この指示だけでは「三三」の禁止を実装しきることは難しい。
ロジックと進め方にまで踏み込んだ指示が必要になる可能性が高い。

```text
石が三つ並んでいる箇所をメモリに格納するようにしてください。
メモリの状態は石を置く度に更新するようにしてください。
白と黒で石が三つ並んでいる箇所があるかをログ出力するようにしてください。
```

これで思ったのと違う挙動する場合は、ログを共有して更なる修正を指示します。

## STEP 5：オレオレルールを足す

自由に追加するフェーズです。プロンプトの形は STEP 4 と同じで構いません。
ルールが複数ある場合は1つずつ確認しながら追加するとトラブルが起きにくいです。

```text
次のルールを追加したいです。いきなり実装せず、まず影響範囲を整理してください。

追加したいルール：
{ここに自分だけのルールを書く}

確認してほしい点：
1. 修正が必要な箇所
2. 影響する範囲
3. 直し方の方針
4. 確認すべきテストケース
```
