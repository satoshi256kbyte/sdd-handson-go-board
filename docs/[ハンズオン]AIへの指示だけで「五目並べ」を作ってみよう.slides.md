## そもそも「五目並べ」とは（ルール確認）

五目並べの基本ルールは次のとおりです。

- 格子状の盤（交点、またはマス）に、2人が交互に石を置く
- 先手が黒、後手が白を使う
- 縦・横・斜めのいずれかの方向に、自分の石を5個連続で並べたら勝ち
  （長連：6個以上並べても勝ちにならないルールもある。詳しくはローカルルールの節を参照）
- 置いた石は動かない・取られない（並べるだけのゲーム）
- 盤が埋まっても決着しなければ引き分け

ちなみに五目並べを競技化したものを「連珠（れんじゅ）」といいます。

## 「五目並べ」のローカルルール

| ローカルルール | よくある扱いの違い | 補足 |
|----------------|--------------------|------|
| ちょうど5個だけ勝ち（長連は勝ちにしない） | 6個以上並んでも勝ちにしない地域と、6個以上でも勝ちにする地域がある | 競技（連珠）では先手の長連は勝ちにならない |
| 三三の禁止 | 3の並びを同時に2つ作る手を「反則」とする家庭と、ふつうに勝ち筋として認める家庭がある | 反則にする場合、先手だけ禁止とすることが多い |
| 四四の禁止 | 4の並びを同時に2つ作る手を反則にするかどうかも地域差がある | これも先手のみ対象にすることが多い |
| 先手・後手のハンデ | 先手が強すぎるので、先手の初手を中央付近に限定する取り決めを置く地域がある | バランス調整のためのローカルな工夫 |
| 盤のサイズ | 15×15 で遊ぶ地域もあれば、家にある紙やマス目に合わせて 9×9 や 19×19 で遊ぶ家庭もある | 盤が小さいほど短時間で決着する |
| 置く場所 | 交点に置く流派と、マスの中に置く流派がある | どちらでもゲームは成立する |

## 余談：AI駆動開発におけるテスト

先日、こんな質問をいただきました。

「AI駆動開発でテストはどうしていますか？テストにAIを使用していますか？」

自動テストをAIに書かせてはいますが、それは回答ではないと思ったので以下のように答えています。

```
AIに指示を出す時に、概要とテストケース（または受入基準）を出力させるようにしています。
テストケースは何を持ってOKとするかの判断基準です。
概要とテストケースを合わせて見ることで、AIが作るものをどう認識しているか把握できます。
これをレビューした上で、そのテストケースを満たすように実装するよう指示しています。

レビュアーはレビューする時、概要とテストケースを重点的にレビューします。
```

ちなみに、AIがテストを無理やり通すように書いてしまう問題については、
ミューテーションテストなどを導入するしかないのかな、と考えています。

## STEP 4の補足と余談

ローカルルールの実装、思い通りの実装になっていますか？
うまくいかない場合は、具体的なことに踏み込んだ指示が必要かもしれません。

あと、修正する度に見た目が微妙に変わっていませんか？
実務では、変えないところは明確に指示する必要があります。

AIは良くも悪くも指示されたことについて一直線に進むのでわりと豪快に直しがちです。
今回は連続している作業なので気にならないと思いますが、
実際の仕事では一度稼働したものを豪快に直すのはNGです。

従って、改修の場合は一旦影響範囲やテストケースを出させて、
既存のものに影響を与えないような直し方や、既存のものがちゃんと動くことについての認識合わせが必要です。
